# Architecture Decision Records (ADR) / Журнал архитектурных решений

Документ фиксирует ключевые архитектурные и продуктовые решения, принятые в процессе проектирования и разработки системы **Flower Catalog AI**.

---

## ADR-01: Расчёт сезонного тренда спроса (`growth`)

* **Контекст:** API Яндекс Wordstat предоставляет временные ряды помесячной частотности (`dynamics`). Требовалось формализовать устойчивый расчет относительного изменения спроса.
* **Решение:** `growth = (last_count - prev_count) / max(prev_count, 1)`. При количестве исторических точек менее 2 метрика принимает значение `None`.
* **Реализация:** `src/clusterer.py` (функция `calculate_growth`).
* **Верификация:** `tests/test_contracts.py`.

## ADR-02: Классификация коммерческого интента (`commercial`)

* **Контекст:** Базовый поисковый спрос содержит как информационный, так и коммерческий трафик. Wordstat API не возвращает готовый интент запроса.
* **Решение:** Внедрен алгоритм нормализации и эвристический анализ коммерческих маркеров («купить», «цена», «доставка», «заказать», «недорого»). Запросы с маркерами классифицируются как коммерческие для приоритизации в каталоге.
* **Реализация:** `src/clusterer.py` (функция `is_commercial`).
* **Верификация:** `tests/test_contracts.py`, `tests/test_wordstat.py`.

## ADR-03: Управление квотами Wordstat и предотвращение Rate Limit

* **Контекст:** Яндекс Wordstat v2 имеет жесткие суточные и секундные лимиты. Длительный сбор ассоциаций через `topRequests` может исчерпать квоту до этапа расчета динамики (`dynamics`).
* **Решение:** 
  1. Реализован лимитер запросов с обязательным резервированием пула для `dynamics` (`WORDSTAT_MAX_REQUESTS` - `WORDSTAT_TOP_CLUSTERS`).
  2. Внедрен паттерн **Circuit Breaker**: при получении HTTP 429 конвейер плавно приостанавливает выполнение с экспоненциальным backoff.
* **Реализация:** `src/wordstat.py` (класс `WordstatClient`).
* **Верификация:** `tests/test_wordstat.py`.

## ADR-04: Структура персистентности и хранение метаданных импорта

* **Контекст:** При пакетном CSV-импорте параметры среза (регион, категория) не должны дублироваться в каждой поисковой фразе.
* **Решение:** Нормализованная схема SQLite: метаданные среза фиксируются на уровне сущности запуска (`runs`/`datasets`), а фразы ссылаются на прогон через внешний ключ, сохраняя компактность и скорость выборок.
* **Реализация:** `src/db.py`, `src/models.py`.
* **Верификация:** `tests/test_db.py`.

---

## ADR-05: Наблюдаемость через Trace Engineering

* **Контекст:** Высокие риски захламления логов, неструктурированного вывода (`print`) и случайной утечки API-токенов в консоль при параллельном выполнении задач.
* **Решение:** Полный отказ от `print`. Разработана легковесная подсистема трассировки `tracer` с иерархическими контекстными спанами, разделением операций на `READ_ONLY` и `MUTATING` и автоматической санитизацией секретов.
* **Реализация:** `src/trace.py`.
* **Верификация:** Покрытие спанами ключевых узлов пайплайна (`src/clusterer.py`, `src/wordstat.py`, `src/image_processor.py`).
